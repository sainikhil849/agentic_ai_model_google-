DISTRICT AGENT - LIVE EXCEL SAVING IMPLEMENTATION
====================================================

PROBLEM SOLVED
==============
"While scraping district events in the terminal its collecting required events 
to the limit but simultaneously store in the excel sheet for every 10 events"

SOLUTION IMPLEMENTED
====================

✓ District Agent now AUTOMATICALLY saves events to Excel every 10 events
✓ File created in: exports/DISTRICT_LIVE_<timestamp>.xlsx
✓ If process stops → Keep all saved events (no data loss)
✓ Real-time progress tracking in Excel file


WHAT WAS CHANGED
================

File: backend/agents/platforms.py

1. Added Imports (Top of file):
   - import os
   - import pandas as pd
   - from datetime import datetime

2. Updated DistrictAgent Class:
   - Added __init__ variables:
     * self.excel_filepath = None
     * self.events_count_saved = 0

3. New Method: _save_events_to_excel()
   Purpose: Save events to Excel every 10 events
   
   Logic:
   - Check if (current_total - last_saved) >= 10
   - If yes → Write all events to Excel
   - If force_save=True → Write regardless (final save)
   
   Features:
   - Creates file only once: exports/DISTRICT_LIVE_20260417_181234.xlsx
   - Updates same file with new events
   - All 16 columns: name, date, time, price, platform, location, etc.
   - Uses pandas for formatting
   - Error handling - won't crash if save fails

4. Modified _perform_scraping_sync():
   - After enriched.append(raw) → Added: self._save_events_to_excel(enriched)
   - Before return → Added: self._save_events_to_excel(enriched, force_save=True)

TROUBLESHOOTING
===============

Issue: Excel file not created
Solution: Check logs for errors, ensure exports/ folder exists

Issue: File not updating
Solution: Restart scraping, check permissions on exports/

Issue: Can't see file while scraping
Solution: It's being updated, Excel might be locked, close and reopen

Issue: Fewer events saved than expected
Solution: Some events rejected (not Hyderabad), this is correct behavior
